# Руководство автора статей

Приложение читают в тяжёлой ситуации, без интернета и без возможности спросить специалиста.
Каждая статья должна быть **полной, точной, понятной неподготовленному человеку** и пригодной к выполнению по шагам.

## Файл статьи

`content/articles/<category>/<slug>.md` — slug и категория строго из `content/PLAN.md`.

```markdown
---
title: Заголовок как в PLAN.md
summary: Одно предложение — о чём статья и главное действие. До 120 символов.
section: Название раздела из PLAN.md (только если у категории есть разделы)
urgency: normal          # critical — угроза жизни в минутах; important — серьёзно/срочно; normal — остальное
sos: false               # true только для экстренных инструкций первой помощи
order: 1                 # порядок внутри раздела (как в PLAN.md)
tags: [3–7 тегов в нижнем регистре, как люди будут искать: синонимы, разговорные слова]
related: [slug1, slug2, slug3]   # 2–6 самых близких по смыслу статей из PLAN.md (в любых категориях)
---
```

## Структура текста

1. Первый абзац (1–3 предложения) — суть: когда это нужно и главное правило.
2. Для экстренных тем — сначала **действия по шагам** (нумерованный список), объяснения после.
3. Заголовки `##` и `###`. Короткие абзацы. Списки вместо сплошного текста.
4. Конкретика вместо общих слов: числа, пропорции, время, размеры, температуры, дозы.
   Плохо: «кипятите достаточно долго». Хорошо: «кипятите 1 минуту после начала сильного кипения».
5. Обязательные блоки, где уместно:
   - «Признаки» / «Как понять»;
   - «Что делать» по шагам;
   - «Чего нельзя делать» — распространённые опасные ошибки и мифы;
   - «Когда это опасно» / «Когда искать медицинскую помощь»;
   - «Из подручных средств» — если нет нужного оборудования.
6. Плашки (используйте умеренно, 0–3 на статью):
   ```markdown
   > [!DANGER]
   > Угроза жизни, необратимые последствия.

   > [!WARNING]
   > Частая ошибка, риск травмы.

   > [!NOTE]
   > Важный контекст.

   > [!TIP]
   > Практический совет.
   ```
7. Таблицы — для сравнений, доз, пропорций.
8. Объём: 300–1200 слов. Экстренные статьи — сжато, но полно.

## Ссылки между статьями

- В тексте: `[обработайте рану](wound-care)` — slug из PLAN.md. Ставьте ссылки там, где читателю реально пригодится перейти (2–6 на статью).
- В `related` — самые близкие статьи; блок «Связанные статьи» строится автоматически из related, тегов и текста.
- Ссылки только на slug из PLAN.md. Сломанные ссылки ломают сборку.

## Термины (всплывающие подсказки)

Непонятные слова объясняются в словаре — `content/glossary/<файл>.json`.
Приложение само находит термины в тексте и делает их кликабельными, отдельно в статье помечать не нужно.

```json
[
  {
    "term": "Жгут",
    "forms": ["жгут", "жгута", "жгуту", "жгутом", "жгуты", "жгутов"],
    "definition": "Тугая лента, которой пережимают руку или ногу выше раны, чтобы остановить сильное артериальное кровотечение.",
    "article": "severe-bleeding"
  }
]
```

- `term` — термин в начальной форме, с заглавной буквы.
- `forms` — **все** реально встречающиеся формы слова в нижнем регистре (падежи, число). Для словосочетаний — формы всего словосочетания («устойчивое боковое положение», «устойчивое боковое положения»…).
- `definition` — 1–2 простых предложения без других терминов.
- `article` — slug статьи, где тема раскрыта (необязательно).
- Добавляйте термины, которые непонятны человеку без специального образования: медицинские, технические, химические (анафилаксия, гипотермия, асептика, инвертор, электролит, щёлок, азимут…). Не добавляйте общеизвестные слова.
- Не заводите термин, у которого есть только одна форма, совпадающая с частым обычным словом.

## Точность — главное требование

- Опирайтесь на актуальные признанные источники: рекомендации ERC/AHA (реанимация), ВОЗ, МККК/Красный Крест, МЧС России, руководства по полевой медицине, агрономические и инженерные справочники.
- Лекарства: международное непатентованное название (+ частое торговое в скобках), форма, доза для взрослых, для детей — **в мг/кг** и возрастные ограничения, максимальная суточная доза, главные противопоказания. Если не уверены в дозе — не указывайте её.
- Не выдумывайте цифры. Если данные различаются — дайте безопасный консервативный вариант.
- Прямо предупреждайте о рисках: ток, газ, химия, давление, огонь.
- Народные методы — только если безопасны; вредные мифы явно опровергайте в «Чего нельзя делать».
- Не публикуйте инструкции по изготовлению оружия, взрывчатых и отравляющих веществ.
- Никаких внешних ссылок и «загуглите» — интернета у читателя нет.

## Язык

Простой русский, повелительное наклонение для действий («Прижмите», «Уложите»), без канцелярита. Термин при первом упоминании — с кратким пояснением в скобках, если он критичен для понимания шага.

# Руководства по ситуациям (категория `guides`)

Руководство — **план действий на конкретный случай**, по которому человек идёт шаг за шагом, не собирая информацию по статьям. Подробности — ссылками на статьи (ссылок много, 15–40 — это нормально). Объём 1500–3500 слов.

## Обязательная структура

1. **Вступление** (2–4 предложения): для какой ситуации, главная цель, главная опасность.
2. `## Главные правила` — 3–7 пунктов, которые спасают жизнь в этой ситуации.
3. **План по времени** — разделы вида `## Первый час`, `## Первые сутки`, `## Первая неделя`, `## Дальше` (или по этапам: «Сборы → В пути → На месте»). В каждом — нумерованные шаги со ссылками на статьи.
4. **Что взять / что должно быть** — чек-листы с галочками (они интерактивные и сохраняются на телефоне):
   ```markdown
   - [ ] Нож с фиксированным клинком
   - [ ] Спички в герметичной упаковке + зажигалка
   ```
   Группируйте по смыслу (`### Документы`, `### Вода`, `### Для детей` …). Для детей — обязательно отдельный список.
5. **Расчёты запасов** — таблицы, которые сами пересчитываются под состав семьи читателя (по умолчанию 2 взрослых + 2 ребёнка):
   ````markdown
   ```supplies days=14 title="Еда и вода на 2 недели"
   Вода питьевая | л | 3 | 2
   Крупы (гречка, рис, овсянка) | кг | 0.25 | 0.15
   Котелок 3–4 л | шт | 0 | 0 | 1
   ```
   ````
   Колонки: `что | единица | на 1 взрослого | на 1 ребёнка | [фиксированно на всю семью]`. При `days=N` значения взрослого и ребёнка — **в сутки**, приложение умножит на N. Без `days` — количество на человека. Последняя колонка (необязательная) — вещи «одна на семью» (котелок, топор, аптечка). **Она НЕ умножается на days** — пишите в неё количество на весь срок таблицы, а не в сутки (например, пакеты для туалета на 14 дней — 30 шт, а не 2). Значения — числа (дробная часть через точку). Не пишите в таблице итоги вручную — приложение считает само.
6. **Еда, если купить нельзя** — где уместно: что реально добыть в этой местности и сезоне, сколько это даёт калорий, честно: хватит ли на семью. Ссылки на `wild-edible-plants`, `fishing`, `trapping`, `mushrooms`, `garden-basics` и т.д.
7. `## Дети` — особенности: темп, тепло, вода, питание, психология, что им нести самим.
8. `## Ошибки, которые убивают` — типичные смертельные ошибки в этой ситуации.
9. `## Когда менять план` — признаки, что пора уходить / возвращаться / искать помощь.

## Единые нормы для расчётов (используйте их, чтобы руководства не противоречили друг другу)

«Ребёнок» = 3–12 лет. Подросток старше 12 — как взрослый. Младенцы и дети до 3 лет — отдельные строки/заметки (смесь, подгузники, пюре).

| Что | Взрослый в сутки | Ребёнок в сутки |
|---|---|---|
| Питьевая вода (умеренный климат, покой) | 3 л | 1,5–2 л (в таблицах 2) |
| Вода в жару / при тяжёлой работе | 4–6 л | 2,5–3 л |
| Вода на готовку и минимальную гигиену | +2 л | +1 л |
| Энергия (обычно) | 2200–2500 ккал | 1400–1800 ккал (в расчётах 1600) |
| Энергия (холод, переходы, тяжёлая работа) | 3000–4000 ккал | 2000 ккал |
| Сухой паёк (крупы, бобовые, сухари, жиры) | ~0,65–0,75 кг | ~0,45 кг |
| Дрова зимой в доме/избе | 10–20 кг на печь в сутки (на семью) | — |

Энергия продуктов: крупы/макароны/мука ~3500 ккал/кг, бобовые ~3000, сахар 4000, растительное масло 9000, сало 7500–8000, тушёнка ~2200, сухое молоко ~5000, орехи ~6000.

Сверяйте свои нормы с [stockpile-list](stockpile-list) и [go-bag](go-bag) — руководства не должны им противоречить (или явно объясняют разницу).

```yaml
sos: false
order: N
tags: [...]
related: [...]
---
```
