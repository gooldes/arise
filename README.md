# Arise — офлайн-справочник по выживанию

PWA на Vite + Preact + TypeScript. Весь контент встраивается в сборку и работает без интернета.

## Команды

```bash
npm install
npm run dev       # разработка: http://localhost:5173 (и по IP в локальной сети — для телефона)
npm run build     # сборка + офлайн-архив
npm run preview   # проверить собранную PWA локально
```

## Сайт

Опубликован на GitHub Pages: **https://gooldes.github.io/arise/**

Обновление: `git push` в ветку `main` — GitHub Actions сам соберёт приложение (`.github/workflows/pages.yml`) и выложит его за 2–3 минуты. Телефоны с установленным приложением подтянут новую версию при следующем открытии с интернетом.

## Запуск локально

```bash
npm install      # один раз
npm start        # собрать и открыть http://localhost:4173
```

- **На компьютере** по адресу `http://localhost:4173` приложение работает полностью: офлайн-кэш, книги, поиск. В Chrome/Edge его можно установить как приложение (значок «Установить» в адресной строке).
- **Без сервера**: откройте `release/arise/index.html` двойным кликом — всё, кроме поиска по тексту книг (книги открываются встроенным PDF-просмотрщиком браузера).
- **С телефона в той же Wi-Fi сети**: `npm run preview` печатает адрес вида `http://192.168.x.x:4173` — по нему можно смотреть приложение, но **сохранить его на телефон для работы без интернета так не получится**: браузеры разрешают офлайн-режим только по HTTPS (или на localhost). Для установки на телефоны приложение нужно будет выложить на хостинг с HTTPS.

## Что даёт `npm run build`

| Путь | Для чего |
| --- | --- |
| `dist/` | Выложить на любой статический хостинг (HTTPS) — это PWA для телефонов |
| `release/arise/index.html` | Открыть двойным кликом на компьютере, без сервера и интернета |
| `release/arise-offline.zip` | Архив для пересылки: распаковал → открыл `index.html` |

Сборка падает, если пакет больше 150 МБ, и предупреждает после 100 МБ.

## Как устроен офлайн

- JS, CSS и **все статьи** встроены в один `index.html` (vite-plugin-singlefile), роутинг через `#`, поэтому работает даже с `file://`.
- `scripts/postbuild.mjs` генерирует `dist/sw.js` со списком **всех** файлов. При первом открытии service worker скачивает их атомарно: либо весь контент, либо ничего.
- Ответы берутся из кэша, сеть не нужна. В «Настройках» видно, что всё скачано.
- Новая сборка = новая версия кэша; пользователь видит «Загружена новая версия».

## Возможности

- **Статьи** по разделам и подразделам, экран SOS, избранное, история.
- **Поиск** по статьям (с учётом словоформ), терминам, книгам и **тексту внутри книг** (с номером страницы).
- **Термины**: слова из словаря (`content/glossary/*.json`) автоматически подчёркиваются в тексте; тап — объяснение и ссылка на статью. Отдельная страница «Словарь».
- **Перелинковка**: ссылки в тексте + блок «Связанные статьи» (ручной `related` + автоподбор по тегам, тексту и ссылкам).
- **Книги**: PDF с офлайн-просмотрщиком (pdf.js) — на Android PDF иначе не открыть без интернета.

## Добавление статьи

Полные правила для авторов — [content/CONTENT_GUIDE.md](content/CONTENT_GUIDE.md), план всех статей — [content/PLAN.md](content/PLAN.md).
`npm run content:report` показывает, что из плана ещё не написано, короткие статьи и статьи без ссылок.


Создайте `content/articles/<категория>/<slug>.md`:

```markdown
---
title: Сильное кровотечение
summary: Одна строка — видна в списках и на экране SOS.
urgency: critical      # critical | important | normal
sos: true              # показать на экране SOS
order: 1               # порядок в разделе
tags: [кровотечение, жгут]
draft: false           # true — пометка «черновик»
updated: 2026-09-24
---

Текст в Markdown. Таблицы, списки, заголовки ## и ###.

> [!DANGER]
> Красная плашка. Также есть [!WARNING], [!NOTE], [!TIP].

Ссылка на другую статью: [реанимация](cpr-adult)
```

Категории — в `content/categories.json` (порядок в файле = порядок на главной).
Сломанные ссылки, неизвестные категории и дубли slug при сборке дают ошибку.

## Книги

1. Положите PDF в `content/books/`.
2. Добавьте описание в `content/books/books.json`:
   ```json
   { "id": "who-pocketbook", "file": "who-pocketbook.pdf", "title": "…", "author": "ВОЗ", "year": 2013,
     "description": "…", "category": "medicine", "license": "CC BY-NC-SA 3.0 IGO", "source": "https://…", "pages": 412 }
   ```
3. `npm run build` — книга скопируется в сборку, а её текст извлечётся для поиска
   (нужен `pdftotext`: `brew install poppler`; у сканов без текстового слоя поиск недоступен).

Следите за общим весом: книги — основной потребитель лимита в 100 МБ.

## Картинки

Только там, где без схемы не обойтись.

1. Положите оригинал в `content/images/` (png/jpg/…; схемы лучше в SVG).
2. В статье: `![Наложение жгута](tourniquet.png)`.
3. При сборке картинка ужимается до WebP (≤ 1200 px, качество 70) в `public/img/`. SVG копируется как есть.
